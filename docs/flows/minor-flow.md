# minor-flow — вертикаль MINOR (`x.Y+1.0`)

## Зачем этот вес

**Добавляем новую способность, ничего не ломая.** В задокументированный контракт **прибавляется**
операция, поле или флаг — а все существующие вызовы работают ровно как раньше. Контракт растёт
**аддитивно**, и новая способность отгружается **выключенной** (тоггл default OFF): этот прогон
доказывает, что деплой здоров, а не что способность выдерживает нагрузку. Транк получает `Y+1.0`.

Minor — это **дельта к [`patch-flow.md`](./patch-flow.md)**: тот же хребет, но с включённым шагом
контракта и обязательным дизайном добавляемой поверхности. Ниже размечена только разница (**Δ**).

## Инвариант веса

Различающий вопрос — **отсутствие → присутствие** новой поверхности, а не «старое значение → новое».
Аддитивность здесь не мнение, а проверяемый факт: **её проверяет машина** (контракт-дифф), и если
находит хоть один ломающий класс изменений (удаление, смена типа, новое обязательное поле) — вес был
выбран неверно, задача останавливается и переклассифицируется как `major`. Инструмент **fail-closed**:
нет чем проверить или формат неоценим — это тоже стоп, а не молчаливый проход. Не «на глаз» и не
суждением ревьюера.

**Причина ≠ вес.** Изменение, ломающее существующего потребителя, — `major`, не minor. Починка под
существующий контракт без новой способности — `patch`, не minor.

Несколько понятий, которые встретятся ниже, объясняются один раз:

- **Дискриминирующий сценарий здесь — `отсутствие → присутствие`:** 404 → 200, поля нет → есть, флаг
  off → эффект. Он должен быть не вырожден (до и после — наблюдаемо разные ответы).
- **Тоггл (фиче-флаг), default OFF.** Новая способность катится выключенной: релиз валидирует деплой,
  а её **включение — отдельный прогон оператора** со своей канарейкой и своим Gate #3; эта вертикаль
  включением не владеет.
- **Дизайн нужен всегда.** Новая поверхность — это контрактное решение (форма, имя, место), и оно
  пиннится один раз до нарезки тикетов. «Нужен всегда» здесь про принимаемое решение, а не про число
  модулей.
- **Существующие контрактные тесты не правятся.** Правка такого теста — сигнал слома, то есть
  неверного веса (это блокер на ревью).

Репозиторий native: замороженный контракт и дизайн-пакет уже в нём, разведки и conform нет;
greenfield-роли нарезки, use-case и скаффолда не запускаются. README **с нуля не пишется**, но
`@dijkstra` **актуализирует** существующий README и «Карту режимов отказа» в change-mode — узко,
только когда дельта трогает документированное поведение (новая поверхность / новый режим отказа).

## Точный контур для исполнителя — Δ к patch

Поток тот же, что у patch, с двумя добавлениями. Первое: **включается шаг контракта** — спека
эволюционирует аддитивно и снова замораживается, а машина подтверждает ноль ломающих изменений.
Второе: **дизайн выполняется всегда** — добавляемая поверхность проектируется, и решение о тоггле
фиксируется в ADR. В тикетах появляется один компонентный тест на **новую** поверхность (RED-first:
«до» = 404/отсутствует/дефолт) и требование тоггла; существующие тесты остаются нетронутыми и
зелёными — это и есть доказательство совместимости. После имплементации, **если добавленная
поверхность видна в документации**, `@dijkstra` актуализирует README и «Карту режимов отказа»
(change-mode, не greenfield-прогон), а `@wirth-moduledesigner` сводит дизайн из `<change-dir>` в
канонический срез `docs/design/<slice>/`, чтобы не копился дрейф. PR идёт с префиксом `feat:`,
тег — `Y+1.0`.

Легенда: **In** · **Out** · **✓** проверка · **⟳** раунды · **тир**. **Δ** — где minor отходит от
[`patch-flow.md`](./patch-flow.md); шаги без **Δ** идентичны ему и здесь даны сжато.

## Δ-сводка — что minor добавляет к patch

1. **Семантика:** отсутствие → присутствие (новая поверхность), а не old → new существующей.
2. **Шаг контракта включается** (`@wirth-apidesigner` эволюционирует замороженную спеку аддитивно).
3. **Аддитивность механическая:** дифф (одно поведение, без флага) = 0 breaking, иначе **STOP → `major`**.
4. **Дизайн выполняется всегда** — новая поверхность есть решение.
5. **Тоггл, default OFF**; включение — отдельный прогон.
6. **Формула тестов:** +компонентный на **новом** API, старый сьют зелёный и **нетронутый** — это и есть
   доказательство совместимости.
7. **`feat: …` / `Y+1.0`** вместо `fix: …` / `Z+1`.
8. **README актуализируется** (`@dijkstra`, change-mode) — узко, только когда дельта трогает документированное
   поведение или «Карту режимов отказа»; на чисто внутренней правке шаг не запускается.
9. **Дизайн из `<change-dir>` сводится в срез** (`@wirth-moduledesigner`, под-шаг приёмки) — против дрейфа
   канонического дизайн-пакета.

## Тиры

**large = суждение** (gilb, triage, change-intake, apidesigner, moduledesigner, ticketer, planner, mills,
linger, fagan, dijkstra). **medium** — hughes-rework, michtom. **small** — wirth-tester, git-hand, ledger. Minor тяжелее
patch ровно на **одну всегда-включённую стадию** (контракт + дизайн добавляемой поверхности) — это цена
корректного расширения контракта; имплементация остаётся точечной.

## Раунды

- Dropout стадии: **retry ≤2** тем же владельцем → `escalate`. `STOP:` — оператору, не dropout.
- Фикс-петля `@linger`: **K=2** → `escalate`.
- Ревью: счётчик у `@mills` (раунд ≥1 с блокером → `escalate`).
- **Ре-триаж по CONTRACT_BREAKING** — не раунд, а смена веса: прогон возвращается к `@wirth-triage`.

## Мониторинг процесса

Идентичен patch ([`patch-flow.md`](./patch-flow.md) §Мониторинг): anti-loop гардрейла, watchdog на
`session.error`, идемпотентность через `.agent/planner/done.log` + `validate-layout`, живая строка izi и
`node harness/progress.mjs .` дословно. Гейты #1/#2/#3 — человеческие, не прокликиваются.
