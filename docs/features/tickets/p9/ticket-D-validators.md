## D1 · contract-diff → диспетчер, одно поведение, fail-closed (P9-1)

Сейчас `validate-contract-diff.mjs` — самописный дифф только по `.json`; YAML → «неоценимо» → exit 0
(на сервисах гейт не проверяет ничего). Переписать:
- **Одно поведение:** breaking → **exit 2**, аддитивно → 0. Флага `--require-additive` **нет** (убрать); режим не
  читается из `mode` — инструмент не знает про веса, разница по весам живёт в конвейере.
- **Диспетчер по формату спеки:** OpenAPI → `oasdiff breaking`; AsyncAPI → `asyncapi diff` (breaking-политика);
  JSON Schema → встроенный структурный дифф (уже есть, зависимостей не требует).
- **fail-closed:** формат распознан, но инструмента нет / не смогли сравнить → **STOP exit 2** с точной командой
  установки (не «пропуск exit 0»). Это принципиальная инверсия текущего `unevaluableExit()`.
- Прежний JSON-Schema-дифф сохранить как встроенную ветку (класс breaking: REMOVED / NEW_REQUIRED /
  TYPE_CHANGED / REMOVED_OP + рекурсия).
- Диспетч по внешним инструментам: вызывать, только если бинарь есть в PATH; парсить его exit-код/вывод.
- Тесты `contract-diff.test.mjs`: additive→0, breaking→2, нет инструмента→2 (fail-closed), встроенный
  JSON-дифф по-прежнему классифицирует; мокать наличие/отсутствие внешнего бинаря.

## D3 · Раскладка: `/debt/` вместо тихого зелёного (P9-6, общий контракт §2)

`lib/validators.mjs:430` (`validateLayout`) матчит только `internal/<slug>/`; на репо без `internal/` путей ноль
→ exit 0, гейт выглядит рабочим (ложное «ок»). Правка в `validate-layout.mjs` (CLI):
- при неприменимости инварианта (нет `internal/` и нет internal-путей) — **явно печатать** «инвариант раскладки
  не действует — репозиторий не по стандарту», **идемпотентно** писать `/debt/task-NNN.md` (репо-корень; `NNN` =
  след. свободный, `ls /debt/`; не плодить дубликат для той же причины — сверять по содержимому/маркеру причины),
  exit 0 (не блокировать прогон).
- Файл долга — чёткая постановка: что не так (layer-keyed/плоская раскладка) · что сделать (привести к
  `internal/<slug>/`) · критерий готовности (`validate-layout` проходит по существу).
- Чистое ядро (эмиссия/выбор NNN) — тестируемо без fs где возможно; тест на идемпотентность (второй прогон не
  плодит второй файл).
