# Тикет — жизненный цикл долга (`/debt/`) и untracked-файлов в прогоне

**Владеет:** `harness/close-run.mjs` (снятие B4), `harness/agents/_shared/git-hand.md` (режимы `start`/`terminal`),
их тесты. **Не трогает:** `validate-layout.mjs` (эмиссия долга остаётся как есть), веса/теги, вайп `.agent/`.

Контекст: общий контракт P9 §2 ([`p9/README.md`](./p9/README.md)) — `/debt/task-NNN.md`, `/debt/` пустой = чисто,
`/debt/` вне `.agent/` ⇒ вайп прогона его не сносит. Тикет **не отменяет** §2, а достраивает недостающее звено:
*кто и каким коммитом фиксирует появление и исчезновение файла долга*.

## Постановка — снятие долга не коммитится (баг)

`close-run.mjs` на закрытии прогона удаляет файл долга **из рабочего дерева**:

- `debtToRemove({ resolvesDebt, merged })` — `harness/close-run.mjs:78–83`, отдаёт `debt/task-NNN.md`;
- `harness/close-run.mjs:206–207` — `rmSync(join(ROOT, debtRel), { force: true })`.

Это удаление **нигде не коммитится**. Единственный git-коммит закрытия стейджит ровно один файл —
`R("git", "add", "docs/changes/LEDGER.md")` (`harness/close-run.mjs:180`), и это осознанно (в транк уезжает
только плумбинг ledger'а). В направлении «ledger выводится из git» ledger-коммита не будет **вовсе**, и тогда
удаление долга не коммитит уже никто.

Следствие в репозитории, где `/debt/` **отслеживается** гитом: после закрытия прогона в рабочем дереве висит
незакоммиченное `deleted: debt/task-NNN.md`. Вайп `.agent/` его не касается (`/debt/` вне `.agent/`), а
следующий прогон подметёт удаление в **чужой PR** — `@git-hand` в `mode=terminal` коммитит `git add -A`
(`harness/agents/_shared/git-hand.md:83`). Тот же класс дефекта, от которого `LEDGER.md` уже защищён
собственным коммитом (комментарий `close-run.mjs:175–177`).

На стенде `pinout-openapi` баг не выстрелил по случайной причине: там `/debt/` целиком **untracked**, удалять из
индекса нечего. В самом мета-репо `/debt/` тоже untracked и не в `.gitignore` — то есть состояние долга сегодня
вообще не воспроизводимо: оно живёт только в рабочем дереве конкретной машины.

## Требование — владелец git-side-effects один, долг фиксируется коммитами

Замысел оператора (это **требование к решению**, не готовый дизайн — дизайн делает исполнитель):

1. **Фиксация на старте.** `/debt/` и вообще untracked-файлы, с которыми прогон начинает работу, коммитятся в
   рабочую ветку **первым коммитом, локально, до начала работы**. Смысл — зафиксировать и сделать
   воспроизводимым входное состояние прогона (сейчас оно неотличимо от мусора рабочего дерева).
2. **Оплата перед PR.** Долг, который этот прогон исполняет, удаляется **перед отправкой PR** — в PR уходит уже
   «оплаченное» состояние, удаление долга видно в диффе PR. После мержа долг считается исполненным.
3. **Откат при отклонении.** PR отклонён → файл долга поднимается обратно из того первого локального коммита;
   ничего не потеряно.
4. **Владелец — `@git-hand`** (единственный владелец git-side-effects, `harness/agents/_shared/git-hand.md`,
   `mode=start` / `mode=terminal`). Фиксация входного состояния — работа `mode=start`, снятие долга — работа
   `mode=terminal` (там же, где `git add -A` → commit → push → PR).
5. **`close-run` перестаёт удалять файл долга сам** — `rmSync` уходит; за `@ledger` остаётся запись факта
   (LEDGER/история) и вайп `.agent/`. Разделение обязанностей: кто владеет git, тот и двигает файлы в git.

## Открытые вопросы (решить до реализации)

- **Что считать «untracked, который надо зафиксировать»?** Слепой `git add -A` на старте затянет мусор
  (артефакты сборки, `.env`, локальные дампы) в первый же коммит. Варианты: только `/debt/**`; whitelist путей;
  всё untracked за вычетом `.gitignore` + STOP на подозрительном. Нужен явный, механически проверяемый предикат —
  иначе `mode=start` станет источником грязных коммитов.
- **Имя долга.** `debtToRemove` требует `^task-\d{3,}$` (`close-run.mjs:80`), `validate-layout.mjs:80` эмитит
  `task-NNN.md`, но в мета-репо реальный долг лежит как `debt/async-consumed-contract.md` — рукописный, вне
  схемы. Механика должна либо принять оба вида, либо явно объявить, что «долг прогона» = только `task-NNN.md`.
- **Конфликт с `git-conventions`?** Скилл (`skills/lib/git-conventions/SKILL.md`) и `@fagan`-граница задают
  «одна задача = одна ветка = один PR» и «коммитим ТОЛЬКО провалидированное состояние» (`git-hand.md`,
  precondition `mode=terminal`). Первый локальный коммит **до** работы — это коммит невалидированного состояния.
  Ответить честно: это допустимое исключение (housekeeping-коммит, не продуктовый диффе) или нарушение, и как
  оно называется в сообщении коммита (`chore(debt):`?), чтобы не ломать чтение веса из Conventional Commits.
- **PR отклонён, а ветка уже удалена** (форж чистит ветки на merge/close, локальную ветку снёс оператор). Откуда
  тогда поднимать файл долга: reflog, тег на первом коммите, или долг должен жить и в транке тоже? Без ответа
  пункт 3 требования не выполним.
- **Мульти-долг.** Прогон закрывает один долг (`resolves-debt`), но untracked на старте могло быть несколько
  файлов долга. Первый коммит фиксирует все, удаляется один — остальные остаются в ветке и уедут в PR как
  новые файлы. Это ожидаемо или нужен отдельный маршрут?

## DoD

- `close-run.mjs` не удаляет файлы из `/debt/` (нет `rmSync` по `debt/`); `debtToRemove` либо удалён, либо
  переехал вместе с владельцем — решение отражено в тестах.
- `@git-hand` в `mode=start` фиксирует входное untracked-состояние по явному предикату; в `mode=terminal`
  снимает исполненный долг **до** открытия PR — удаление видно в диффе PR.
- Тест: в репо с **отслеживаемым** `/debt/` после полного цикла (start → terminal → close) рабочее дерево
  чистое — нет незакоммиченного `deleted: debt/*`; следующий прогон не тащит чужое удаление в свой PR.
- Тест: отклонённый PR → файл долга восстановим из первого коммита ветки.
- `node --test harness/test/*.mjs` зелёный; смоук-паритет гардрейлов не сломан.
- Ответы на открытые вопросы записаны в тикете (или в ADR) **до** кода — решения, а не умолчания.
