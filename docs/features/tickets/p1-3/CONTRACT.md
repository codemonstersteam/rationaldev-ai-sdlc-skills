# P1–P3 Онбординг — общий контракт (согласован между пакетами)

Источник — [`../../harness-hardening-and-onboarding.md`](../../harness-hardening-and-onboarding.md) §P1–P3 и
поправка FRD UC-6 в `requirements/semver-verticals.md`. Три пакета делят этот контракт; менять — только всем сразу.

## Смысл (из P0/UC-6)

Онбординг **дотягивает свой легаси до текущего стандарта** — репозиторий, который харнес когда-то построил, но
стандарт с тех пор ушёл вперёд. Направление подстройки: **легаси под стандарт**, не наоборот (это НЕ conform).
Два режима: `reconcile` (пакет есть, но отстал → свести) — основной; `onboard` (пакета фактически нет →
восстановить с нуля) — крайний случай того же.

## Маршрут и веса

- Токен маркера `.agent/planner/mode` = **`onboard`** (новый, добавить в белый список `wirth-triage`). Единый
  токен на оба режима; сам режим `reconcile|onboard` роль определяет по наличию/свежести дизайн-пакета.
- Триаж роутит `route=onboard`, когда репо несёт продуктовый код, но дизайн-пакет
  (`docs/design/slice-*/{module-tree,contracts,c4}.md` + `api-specification/`) отсутствует или отстал от
  стандарта. Строго-**посторонний** репо (харнес не строил, замысел неизвестен) → **STOP** (UC-6 Extension 1a).
- **Вес no-bump:** `ci/semver-bump.mjs` уже возвращает `tag=null` для нераспознанного веса — тега нет, канарейки
  нет. `@ledger` всё равно **закрывает прогон** (запись в `LEDGER.md` + вайп `.agent/`), иначе состояние течёт.
- Гейты: **#1** (акцепт восстановленного пакета) + **#2** (мерж docs-PR). **Gate #3 нет** — продуктового
  релиза нет, меняются только `docs/` и `api-specification/`.

## Роль `@wirth-onboard` (izi-имя — из закрытого набора; предложить, напр. Naur)

- Пишет **только** `docs/**` и `api-specification/**`. Продуктовый код НЕ трогает никогда.
- Восстанавливает/сводит: `docs/design/slice-*/{module-tree,contracts,c4}.md`, корневой `CONTEXT.md`
  (при ≥2 контекстах — `CONTEXT-MAP.md`), `api-specification/*` (замороженный по факту), `AGENTS.md`.
- Определяет **target** (`service|cli`) по коду → пишет `.agent/planner/target` (см. §Target ниже).
- **Провенанс обязателен на каждой записи:** маркер `[as-is]` (описывает как реально построено) или `[gap]`
  (расходится с задокументированным поведением ИЛИ с текущим стандартом). `[gap]` **НЕ «чинить» задним числом** —
  расхождение выносится как долг/заметка оператору (это защита от «дизайна задним числом»).
- Возвращает строку: `wirth-onboard → package ready (mode=<reconcile|onboard>, target=<…>, N slices, G gaps)`
  либо `STOP: <reason>` (напр. строго-посторонний репо).

## Провенанс — формат (единый)

Каждая запись восстановленного пакета несёт inline-маркер `[as-is]` / `[gap: <в чём расхождение>]`.
`validate-package.mjs` проверяет, что **непомеченных** записей нет. Формат маркера один для всех трёх пакетов.

## Target (чинит и SemVer-вертикали — P1–P3 §.agent/planner/target)

`.agent/planner/target` (`service|cli`) сейчас не пишет никто → `validate-dod.mjs` берёт дефолт `service` и
ищет `openapi.yaml` в CLI-проекте, падая в конце цикла. Фикс:
- `@wirth-onboard` пишет `target` (он реконструирует пакет — знает форму);
- `@change-intake` на SemVer-вертикалях **читает target из дизайн-пакета** (или пишет маркер), чтобы `@fagan`
  брал верный профиль. Это общий фикс для patch/minor/major, не только онбординга.

## Приёмка пакета — ПОД-ШАГ Gate #1 (не 4-й гейт)

`@mills` ревьюит полноту восстановленного пакета через `validate-package.mjs` (артефакты на месте + провенанс
размечен). Решение «три гейта» не пересматривается — это часть Gate #1, не новый гейт.

## `validate-package.mjs` (пакет 2) — узко

Проверяет **полноту пакета** и **разметку провенанса**, НЕ подменяет `validate-contract-frozen`/`validate-dod`:
- `docs/design/slice-*/` содержит `module-tree.md`, `contracts.md`, `c4.md`; корневой `CONTEXT.md`;
  `api-specification/` непуст;
- каждая запись несёт провенанс-маркер `[as-is]|[gap]` — непомеченных нет (иначе exit 1 + перечислить).
Чистое ядро (io: none) + CLI-хвост; юнит-тесты.
